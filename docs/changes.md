# 이 폴더는 우리가 쓴 코드가 아니다

David Li 의 **Fluid Paint** (https://david.js.org 아님 — https://david.li/paint) 를
그대로 가져온 것이다.

- 원본: https://github.com/dli/paint
- 라이선스: MIT (`LICENSE` 참고). 저작권 표기를 지우지 말 것
- 가져온 날: 2026-09-29, `master` 최신

## 돌리는 법

빌드 단계가 없다. 순수 JS + GLSL이고 셰이더를 실행 중에 불러온다.
`public/` 아래 있으므로 Vite 개발 서버가 그대로 내보낸다.

```
pnpm dev        →  http://localhost:5173/              (여기로 리다이렉트된다)
                   http://localhost:5173/?studio       (직접 만든 엔진)
```

디렉터리 경로 `/fluid-paint/` 는 Vite의 SPA 폴백에 걸리므로
`/fluid-paint/index.html` 까지 적어야 한다.

## 구조

```
paint.js        전체 조율, 입력, UI
brush.js        붓털 시뮬레이션 (마디 10개 × 붓털 N가닥, PBD)
simulator.js    물감 유체 (이류·발산·자코비·투영) 와 스플랫
wrappedgl.js    WebGL1 래퍼
shaders/        위 전부의 GLSL
```

WebGL**1** 이다. 우리 쪽 엔진(`src/paint`)은 WebGL2를 쓴다.


## 붓이 흐물거려 빗살이 남던 것

원본은 어떤 획을 그어도 붓털 옆면이 **빗처럼 통째로** 드러났다. 원인이 둘이다.

1. **붓이 늘 누워 있었다.** 붓털 길이가 `4.5×scale` 인데 붓 몸통은 `2.0×scale`
   높이에 고정이라, 붓털 길이의 절반 이상이 캔버스 아래로 박힌 채 평면 제약에
   밀려 옆으로 눕는다.
2. **붓털이 뿌리 한 마디만 고정이었다.** 나머지 아홉 마디가 전부 흐물거려서
   붓을 움직이면 붓털 끝이 뒤로 길게 끌리고, 그 궤적 하나하나가 빗살로 남는다.

실제로는 붓을 세워 쓰기도 하고, 그때는 붓 끝만 눌려 결이 약간 보일 뿐이다.
그래서 셋을 값으로 열었다.

| 슬라이더 | 무엇을 |
| --- | --- |
| Brush Upright | 붓 몸통 높이 2.0(눕힘) ~ 4.05(세움) |
| Brush Tilt | 붓털 다발을 한쪽으로 기울인 각. 한 붓 안에서는 고정 |
| Paint Slip | 붓이 유체를 미는 힘. **물감이 콧물처럼 늘어지는 것과 가운데가 파이는 것을 막는 것은 이쪽이다** |
| Bristle Density | 붓털 밀도 분포. 0.5 가 원본(면적당 균일), 높을수록 가운데가 빽빽 |
| Bristle Gather | 붓털이 붓대에서 얼마나 멀어질 수 있는가. **한 번 눌렀을 때 별처럼 흩어지는 것을 막는 것은 이쪽이다** |
| Brush Stiffness | 형태를 유지하는 마디 수 1~9. 움직일 때 빗살이 남는 것을 막는다 |

휨 제약(`u_stiffnessVariation`)도 열어서 2.4 까지 올려 봤지만 거의 듣지 않았다.
실제로 듣는 것은 고정 마디 수다. 여섯 마디쯤이면 붓이 형태를 지킨 채 눌려
결만 약간 보인다.

### 주의: 두 마디를 고정하면 0/0 이 난다

`distanceconstraint.frag` 는 쌍의 가중치 합으로 나눈다. 원본은 뿌리만 고정이라
(0,1) 쌍의 가중치가 (0,1) 이었는데, 두 마디를 고정하면 (0,0) 이 되어 분모가 0 이
된다. NaN 이 붓털을 타고 번져 좌표가 통째로 날아가고 아무것도 그려지지 않는다.
`max(sum, 0.0001)` 로 막는다.

(원본에도 NaN 이 하나 있다. 0번 붓털은 `sqrt(bristleIndex + jitter)` 에서
음수의 제곱근이 나온다. 붓털 하나라 눈에 띄지 않는다.)


## 붓털이 별처럼 흩어지던 것

꾹 눌러 점 하나를 찍어도 붓털이 사방으로 뻗어 별 모양이 됐다. 원본의 평면
제약이 **z 만** 보기 때문이다.

```glsl
if (position.z < 0.0) position.z *= 0.5;
```

붓을 누르면 붓털이 캔버스에 밀려 사방으로 퍼지는데, 가로 방향으로는 아무도
붙잡지 않는다. 20 번 반복하는 동안 한 올 한 올이 제 갈 길로 뻗는다. 실제 붓은
털이 묶여 있어서 눌러도 다발이 유지된다.

`planeconstraint.frag` 에 반지름 제약을 더했다. 붓대에서 `gather × scale` 보다
멀어진 털은 끌어당기되, 딱 자르지 않고 넘친 만큼의 1/4 만 남겨 가장자리 털이
조금 삐져나오는 여지는 둔다.

이것만으로 한 번 눌렀을 때 **동그란 점**이 나오고, 획은 **일정한 두께**로
채워진다. 물감 재질·결·광택은 원본 그대로다.

처음에는 붓털 하나의 자국 반지름(`SPLAT_RADIUS`)을 키워 털을 합치려 했는데,
0.18 만 돼도 자국이 붓보다 커져 뭉개졌다. 필요한 건 자국을 키우는 게 아니라
**털을 묶는 것**이었다. `SPLAT_RADIUS` 는 원본값 0.05 그대로 둔다.


## 물감이 콧물처럼 늘어지고 가운데가 파이던 것

두 증상의 뿌리가 같다. 붓이 유체를 너무 세게 민다 (`SPLAT_VELOCITY_SCALE = 0.14`).

나선을 그려 안을 채우고 반지름별 물감 두께를 재 보면 분명하다.

| Paint Slip | 안쪽 → 바깥 |
| --- | --- |
| 1.0 (원본) | 25 → 31 → 32 → 33 → **36** |
| 0.35 | 32 → 41 → 42 → 31 → 18 |
| 0.10 | **29 → 27 → 22 → 16 → 9** |

원본은 물감이 바깥으로 밀려 나가 가운데가 팬다. 낮추면 붓이 놓은 자리에
그대로 쌓여 가운데가 봉긋한 둔덕이 된다 — 실제로 붓으로 문질렀을 때의 모양이다.

기본값 0.3. 0 으로 두면 물감이 전혀 안 끌리고, 1 이면 원본이다.

### 붓털 밀도

원본의 `sqrt(i/N)` 은 **면적당 밀도가 균일한** 분포다 (Vogel/해바라기).
수학적으로 고른 분포지만 실제 붓은 가운데가 빽빽하고 가장자리로 갈수록 성기다.
지수를 열어 뒀다 — `pow(i/N, density)`, 0.5 가 원본, 기본값 0.65.

바깥쪽 붓털은 `i=N` 에서 `r=1` 로 그대로라 붓 크기는 변하지 않고 안쪽만 모인다.


## 패널 크기가 상수로 박혀 있다

패널 배경과 색상환은 WebGL 로 그리는데 그 안의 옵션은 DOM 이다. `PANEL_HEIGHT`
와 `COLOR_PICKER_TOP` 이 상수라, 슬라이더를 하나 넣을 때마다 브라우저에서 재서
두 숫자를 맞춰야 한다. 빠뜨리면 색상환이 패널 밖으로 나간다.

`paint-engine` 브랜치에는 이걸 DOM 에서 재도록 고쳐 둔 것이 있다. 이 브랜치를
계속 쓸 거라면 그쪽 `measurePanel()` 을 가져오는 편이 낫다.


## 빨리 그으면 획이 달라지던 것

원본은 프레임마다 붓을 새 마우스 위치로 **한 번에 점프**시키고 그 사이를
캡슐 하나로 잇는다. 그래서 같은 획도 속도에 따라 전혀 다르게 나온다.

- 느리게: 캡슐이 잔뜩 겹쳐 물감이 두껍게 쌓인다 (뭉침)
- 빠르게: 긴 캡슐 몇 개로만 그려져 얇고 각지다

여기에 더해, 붓털 속도가 **프레임당 이동량**으로 정의된다 (`updatevelocity.frag`).

```glsl
vec3 velocity = projectedPosition - position;
```

그래서 빨리 그을수록 유체를 미는 힘이 그만큼 커지고, 물감이 붓을 따라 길게
끌려가며 밀린 자국이 남는다. 실제 붓은 빨리 움직인다고 물감을 더 세게 밀지
않는다 — 더 얇게 바를 뿐이다.

둘 다 고쳤다.

1. **이동을 잘게 나눈다.** 프레임당 이동 거리를 `brushStep × 붓 반지름`
   (0.3) 으로 나눠 최대 6 번까지 붓을 옮기고 그때마다 찍는다.
2. **붓털 속도에 상한을 둔다.** `u_maxBristleSpeed` = 붓 반지름의 0.5 배.

획 길이 방향 두께의 변동률 (표준편차/평균):

| 프레임 수 (적을수록 빠른 획) | 전 | 후 |
| --- | ---: | ---: |
| 8 (빠름) | 0.257 | **0.077** |
| 20 | 0.175 | **0.076** |
| 60 (느림) | 0.041 | 0.035 |

평균 두께도 5.5 / 6.7 / 7.3 (33% 차이) 에서 4.3 / 5.0 / 5.3 (23%) 으로 좁혀졌다.

비용: 아주 빠른 획에서는 붓 시뮬레이션(제약 20 회 반복)을 한 프레임에 최대
6 번 돌린다. `maxBrushSteps` 로 조절한다.


## 한국어 UI · 물감 팔레트 · 색 고르개

`paint-engine` 브랜치에서 가져왔다. 붓 엔진과 무관한 부분이라 그대로 옮겨진다.

- `colorpicker.js`, `shaders/picker.frag` — 색상환 고리 → 큰 사각형 + 세로 띠 둘
- 옵션 이름을 한국어로. 이름만으로 모르는 것에는 한 줄 설명
- 유화 안료 16칸 + 쓰던 색 8칸. 칸 색은 엔진과 같은 변환으로 칠한다
- 붓 커서 (원본은 `cursor: none` 인데 대신 그리는 것이 없었다)
- 패널 높이를 DOM 에서 잰다 (`measurePanel`)

### 물감 양

색 고르개 오른쪽 띠다. 원본에서 이름이 어디에도 안 적혀 있어서 뭘 바꾸는지
알 수 없었다. 붓털 하나가 한 번에 놓는 물감의 농도다.

```js
var alpha = mix(minAlpha, maxAlpha, this.brushColorHSVA[3]);
splatColor[3] = alpha;
```

붓털이 100 가닥일 때 0.002 ~ 0.025 사이를 오간다. 이 값은 세 군데로 간다.

1. 색을 덮는 비율
2. 물감 두께 — 한 장짜리 텍스처의 a 가 높이이기도 하다
3. 유체를 미는 힘 (`splatVelocityScale` 에 곱해진다)

그래서 낮추면 옅고 얇고 잘 안 밀리는 글레이즈가 되고, 올리면 진하고 두껍고
잘 끌리는 임파스토가 된다. 기본값 0.8.

### 레이아웃

색 고르개를 패널 **맨 위**로 옮겼다. 옵션이 아홉 개로 늘면서 패널 내용이
1223 px 이 됐는데, 가장 자주 쓰는 색이 맨 아래 있으면 매번 스크롤해야 한다.

`#ui` 는 `pointer-events: none` 이어야 한다. `auto` 로 두면 이 div 가 클릭을
가로채서 **밑의 캔버스에 그린 색 고르개를 집을 수 없다.** 휠 스크롤은
`onWheel` 이 좌표를 보고 대신 처리한다.
